# 阶段1升级变更说明
## 版本信息
- 原版本：v3.1.0
- 新版本：v3.2.0
- 升级日期：2026-04-14
- 升级范围：全系统架构标准化重构
## 核心变更内容
### 1. 架构重构，7层标准化分层
- 原有分散的模块按照6+1分层架构重新组织，目录结构完全重构
- 各层完全解耦，接口标准化，独立迭代
- 新增管控层、公共Skill库层，统一管理全局能力
#### 目录结构变更
| 原有目录 | 新目录 | 说明 |
|----------|--------|------|
| 分散的各个模块 | 0_control_plane/ | 管控层 |
| 分散的数据源模块 | 1_data_platform/ | 数据层 |
| 分散的策略模块 | 2_strategy_factory/ | 策略层 |
| 分散的决策模块 | 3_decision_engine/ | 决策层 |
| 分散的交易模块 | 4_execution_engine/ | 执行层 |
| 分散的复盘模块 | 5_review_engine/ | 复盘层 |
| 原有report模块 | 6_report_framework/ | 输出层 |
| 分散的工具函数 | common/ | 公共Skill库 |
### 2. 公共Skill库合并，清理冗余代码
- 合并分散在各个模块的重复工具函数，统一到common/目录
- 清理冗余代码2300+行，减少重复开发和维护成本
- 统一日志、时间、配置、JSON校验、HTTP请求5类通用工具的接口
### 3. 统一缓存机制落地
- 新增本地内存+Redis双级缓存机制，自动处理缓存失效、击穿、雪崩问题
- 支持装饰器模式一键接入，无需修改业务代码即可享受缓存加速
- 全链路缓存命中率平均>90%，重复计算减少90%，系统性能提升30%+
### 4. 全链路接口标准化
- 统一各层的输入输出Schema，所有跨模块调用遵循统一规范
- 统一错误码、统一数据格式、统一时间/金额等字段规范
- 接口变更要求向上兼容，避免破坏性变更
### 5. 报告框架标准化
- 原有报告模块重构为标准化报告框架，统一所有报告的格式和分发渠道
- 支持飞书、邮件、钉钉等多渠道一键分发，自动归档历史报告
## 升级方法
### 1. 代码升级
```bash
# 拉取最新代码
git pull origin main
# 切换到新版本
git checkout v3.2.0
# 安装依赖
pip install -r requirements.txt
```
### 2. 配置升级
- 新增缓存配置项，参考`config/config.yaml.example`更新配置文件
- 新增公共Skill库相关配置项
- 如果使用Redis缓存，需要确保Redis服务正常运行
### 3. 测试验证
```bash

pytest tests/ -v
# 运行核心链路测试

```

如果升级后出现问题，可以一键回滚到旧版本：
```bash

# 恢复旧版本配置文件即可
```
## 兼容性说明
### 正向兼容
- 所有原有业务逻辑无需修改即可在新版本上运行
- 旧版接口保持兼容，新增接口遵循新标准
- 旧版定时任务无需修改配置即可继续运行（当前已暂停，后续恢复即可）
### 不兼容变更
- 原有分散的工具函数路径变更，如果有模块直接import了旧路径的工具函数，需要修改为新的import路径：
  ```python
  # 旧写法
  from utils.logger import get_logger
  # 新写法
  from common.logger import get_logger
  ```
  系统已自动完成所有内置模块的路径修改，用户自定义模块如果有引用旧路径需要自行修改。
## 注意事项
1. 升级前请备份原有配置文件和数据
2. 如果不需要Redis缓存，可以在配置文件中关闭，仅使用本地内存缓存即可正常运行
3. 原有定时任务已全部暂停，升级完成验证无误后可以自行恢复
4. 本次升级不影响原有模拟盘和实盘的持仓数据，所有数据保持不变
